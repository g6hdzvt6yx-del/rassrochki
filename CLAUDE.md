# Рассрочки — правила работы в репозитории

## Ветки и сайт

- Рабочая ветка — `main`. От неё начинается каждый сеанс, в ней лежит актуальный код сайта.
- Сайт (GitHub Pages) публикуется автоматически при каждом пуше в `main`: `.github/workflows/deploy.yml` — `npm ci` → `npm test` → `npm run build` → публикация. Если тесты падают, сайт не обновляется.
- Сеанс Claude Code работает в своей ветке `claude/*`, созданной от `main`. Пуш или вливание в `main` сразу публикует сайт, поэтому это делается, когда владелец просит выложить изменения (например, «залей на сайт»), и только после того, как проходят `npm test` и `npm run build`.
- Перед вливанием подтяни свежую `main` (`git fetch origin main`), перенеси свои коммиты поверх неё и повтори проверки. Историю `main` не переписывать, force-push в `main` не делать.
- Ветка `codex/web-version` — архив кода сайта до 1 ноября 2026 года. Её история входит в `main`; в неё не пушить.

## Проверки

- `npm test` — тесты (vitest), `npm run build` — сборка (vite).
- Пакет `xlsx` в `package.json` скачивается с `cdn.sheetjs.com`. Если облачная среда не пускает туда `npm ci`, установи остальные зависимости по lock-файлу, а `xlsx@0.18.5` из npm положи только локально. `package.json` и `package-lock.json` ради этого не менять.

## Устройство

- `src/WebAccess.jsx` — вход и роли (администратор / оператор), `src/rassrochki.jsx` — приложение администратора, `src/OperatorDesk.jsx` — кабинет оператора.
- `src/finance.js` — финансовые расчёты (прибыль, поступления, периоды) с тестами в `src/finance.test.js`.
- Данные — Supabase; SQL-схемы и миграции в `supabase/`. Подробности — в `README.md`.
- Интерфейс на русском; тёмная тема — `src/darkTheme.css`.
