# Рассрочки — веб-версия

Отдельная копия актуального приложения Mac от 18 октября 2026 года. Установленное приложение и локальная SQLite-база не изменялись. Клиентские данные и чеки в эту папку не переносились.

## Реализовано
- Вход через Supabase Auth; доступ закрыт до получения активной роли из app_members.
- Администратор: существующее приложение, управление доступом операторов, назначение договоров, история звонков.
- Оператор: только назначенные договоры; просрочки, ближайшие 3 дня, повторные звонки, обещания, журнал результатов.
- Оператор получает ограниченную проекцию через RPC: без закупочной стоимости, наценки, вкладчиков, сканов и внутренних комментариев.
- Звонки хранятся отдельно от платежей. Сообщение об оплате не погашает задолженность.
- Ограничения базы: RLS и узкие RPC. Роль нельзя изменить из браузера.

## Подключение базы
Для восстановленной старой схемы подготовлен 000_upgrade_existing.sql: добавляет владельца записей и недостающие поля вкладчиков; запускать в одной транзакции с 002_roles.sql и назначением подтверждённого администратора. Проверен на модели старой схемы с сохранением существующей записи.

Файл 001_schema.sql предназначен ТОЛЬКО для новой пустой базы. Для существующего проекта сначала проверить таблицы, политики, функции и владельцев данных; не применять схему вслепую.

1. В новой базе выполнить supabase/001_schema.sql, затем supabase/002_roles.sql.
2. В Supabase Authentication отключить самостоятельную регистрацию, создать владельца. Командой в конце 002_roles.sql назначить его администратором.
3. Создать операторов в Authentication; администратор задаёт им доступ по почте в интерфейсе. Создание паролей и рассылка приглашений из браузерного приложения не реализованы.
4. Настроить VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY в окружении сборки. Только публичный anon/publishable key. Никаких service_role.
5. Назначить договоры операторам. Проверить вход владельцем, оператором и заблокированным пользователем; прямые запросы на изменение финансов должны быть запрещены.
6. Настроить адрес сайта в Authentication; проверить рабочую базу и только затем публиковать.

.env.local содержит локальные настройки существующего исходного проекта, исключён из Git. 18 октября 2026 проект восстановлен; после проверки старой схемы применены 000_upgrade_existing.sql и 002_roles.sql одной транзакцией с назначением подтверждённого администратора. Вход администратора в браузере с паролем ещё не проверен. Источник данных Mac — SQLite; он не синхронизируется автоматически с Supabase. Перенос данных требует отдельного проверенного импорта.

## Проверки и ограничения
npm test; npm run build.
Серверный smoke-test: node scripts/check-access.mjs /absolute/path/to/pglite/dist/index.js (временная зависимость вне проекта).

Первоначально назначения сделаны на уровне договора; несколько договоров одного клиента могут появиться отдельными строками. Общая карточка клиента и автоматическое объединение очереди — последующая доработка.
Десктопные резервные копии, корзина и локальный журнал не превращены в облачные аналоги. Журнал звонков облачный, остальные действия администратора требуют отдельного облачного аудита.
Периодические обновления: права — каждые 30 секунд, очередь — каждые 60 секунд и при возврате во вкладку. Сервер проверяет права при каждом запросе.
